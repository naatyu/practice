# Model releases and infrastructure evidence

Snapshot, 19 November 2026. I screened recent public releases first, then included earlier reports when they explained an inherited system or a relevant technique. The table distinguishes reports with a systems section from cards and announcements, which may only establish architecture, a deployment option, or a workload. Multiple versions from one model family are deliberately included for change tracking and should not be treated as independent corroboration. Measurements below are the authors' or vendors' results for their stated workloads.

**Microsoft name check.** I did not find a first-party release under the exact name **MAI Thinking 2**. Microsoft's November 17 Ignite announcement documents MAI Code 2 and Code 2 Flash. Microsoft's MAI Thinking 1 has a separate report. All three are included below under their published names. [Ignite announcement](https://microsoft.ai/news/microsoft-ignite-2026/) · [MAI Thinking 1 report](https://microsoft.ai/pdf/mai-thinking-1.pdf)

## Systems sources that change the learning priorities

| Source | Concrete engineering result or design | Exercise it motivates |
| --- | --- | --- |
| [EUROPA/JUPITER with TorchTitan](https://pytorch.org/blog/training-a-1t-parameter-moe-on-eu-public-infrastructure-with-pytorch-and-torchtitan/) | The authors report about 90 to 1,300 tokens/s/GPU over multiple changes on 384 GH200 GPUs per data-parallel replica. Full activation checkpointing, CPU offload of boundary activations, optimizer-aware parameter placement and FSDP allocator behavior all mattered. | Plot the memory/step-time curve and inspect allocator behavior. Treat the published aggregate gain as a bundle of changes. |
| [DeepSeek DeepEP](https://github.com/deepseek-ai/DeepEP) | Dedicated GPU-side dispatch/combine around expert execution. | Relate your CPU EP implementation to token memory layout, skew, communication/computation overlap and total bytes moved. |
| [HyScale](https://arxiv.org/abs/2610.32057) | The authors identify learned sparse attention's selection step as a bottleneck and propose streaming exact top-k plus replay of indices during recomputation. | Implement fused score/top-k parity and measure recomputed work and temporary allocation. |
| [OpenAI/Microsoft production networking](https://cdn.openai.com/pdf/resilient-ai-supercomputer-networking-using-mrc-and-srv6.pdf) | The authors describe multipath RDMA and failure handling for synchronous training on large fabrics. | Practice collective size sweeps and slow-rank diagnosis. Model how network faults affect recovery time. |
| [DeepMind Decoupled DiLoCo](https://deepmind.google/blog/decoupled-diloco/) | Training experiments with failures and mixed TPU generations expose the availability impact of synchronization strategy. | Compare synchronous stragglers and recovery on a small controlled experiment. Learn the synchronous baseline first. |
| [PyTorch Distributed Checkpoint](https://docs.pytorch.org/docs/main/distributed/checkpoint.html) | Parallel state save/load and load-time resharding. | Validate deterministic resume, measure save stalls, and test reading across shard layouts. |
| [PyTorch Flight Recorder](https://docs.pytorch.org/tutorials/unstable/flight_recorder_tutorial.html) | Inspection of collective execution during stuck distributed jobs. | Diagnose one mismatched or slow-rank run and collect evidence that distinguishes the failure modes. |
| [vLLM optimization](https://docs.vllm.ai/en/stable/configuration/optimization/) and [metrics](https://docs.vllm.ai/en/latest/design/metrics/) | Token budgets and chunked prefill affect scheduling, queueing and cache pressure. | Build a fixed-budget continuous batcher and measure tail latency as well as throughput. |
| [Nsight Compute triage](https://docs.nvidia.com/nsight-compute/ComputeTriage/) | Profile representative runs and investigate the current limiter, using system timelines to pick the kernel when needed. | Produce one trace-backed performance explanation per CUDA exercise. |

Across the high-disclosure cases, the recurring theme is controlling the cost of moving activations, parameters, tokens and cache state. Scheduling, numerical formats and GPU kernels are ways to change that cost. Data loading and failure recovery belong in the plan because hiring and runtime documentation expose them much more directly than most model cards.
